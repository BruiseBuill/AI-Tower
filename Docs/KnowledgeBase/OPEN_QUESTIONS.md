# 待确认问题

以下问题会影响玩法或长期数据结构，AI 不得擅自视为已确定。无需一次全部回答；按当前
开发阶段逐步确认即可。

## P0：开始垂直切片前需要确认

1. 屏幕方向是横屏还是竖屏？是否锁定方向？
2. 玩家具体如何派出进攻单位：点击入口生成、拖拽到部署区、选择路径后派出，还是
   其他方式？
3. 单位生成后是否完全自动行动？玩家能否中途改道、集火、释放技能或撤退？
4. 地图路径是固定路线、多个可选岔路，还是允许自由寻路？单位能否破坏或绕过地形？
5. 玩家在单局内消耗什么资源？资源如何获得，是否随时间恢复？
6. 最基本的胜利目标是什么：摧毁基地、让一定数量单位到达终点，还是完成其他目标？
7. 最基本的失败条件是什么：资源耗尽、时间结束、可用单位耗尽，还是目标受损？
8. 第一种进攻单位和第一种防御塔分别有什么最小行为？

## P1：成长与关卡框架前需要确认

1. 成长是局内、跨关卡永久成长，还是两者都有？
2. 成长对象是单位属性、可用单位种类、主动能力、出兵容量，还是其他系统？
3. 关卡是线性解锁、分支地图，还是可以自由选择？
4. 重复挑战是否提供收益？关卡是否有星级或其他评价？
5. 失败是否消耗资源，是否允许无成本重试？
6. 教学是独立关卡、关卡内引导，还是两者结合？

## P2：内容生产前需要确认

1. 首批计划有哪些进攻单位、防御塔和地形机制？
2. “十余关”的大致章节划分和每章新增机制是什么？
3. 是否有 Boss、防御核心或特殊目标？
4. 是否需要速度切换、暂停观察或关卡预览？
5. 正式素材的风格、像素密度、相机视野和单位相对尺寸规范是什么？

## P3：发布准备前需要确认

1. Android 最低系统版本和目标设备档位。
2. 包名、产品名、图标和版本规则。
3. 存档槽、清档、局中保存与损坏恢复的最终体验。
4. 是否需要震动、刘海安全区、系统返回键行为和应用暂停处理。
5. 发布渠道及其签名、隐私与合规要求。
