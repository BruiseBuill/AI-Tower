# 开发流程与状态

## AI 开发流程

1. 读取根目录 `AGENTS.md` 和本知识库相关章节。
2. 明确本次任务的玩家价值、范围和手动验收条件。
3. 检查现有代码与场景，优先扩展 `BaseFramework`，避免重复系统。
4. 先实现最小可玩闭环，再增加表现和扩展点。
5. 使用稳定内容 ID 和占位资源完成表现，不绑定最终素材。
6. 确认可用的编译/Console 状态，不以历史日志冒充当前验证。
7. 更新本文件的实现状态以及必要的决策记录。
8. 向用户说明改动、当前限制和短小的手动验收步骤。

## 用户手动验收模板

每个功能交付时应给出类似以下内容：

1. 用项目指定的 Unity 版本打开工程和指定入口场景。
2. 清空或观察 Console，进入 Play Mode。
3. 按明确操作完成成功路径。
4. 按明确操作覆盖至少一个失败或边界路径。
5. 退出并重新进入，若涉及存档则确认状态是否保持。
6. 涉及触屏差异时，在 Android 设备上重复关键步骤。

不是所有任务都需要六步；应根据改动缩减。

## 当前入口与手动验收

入口场景：`Assets/Scenes/Level001.unity`（构建列表第 1 位）。

垂直切片手动验收步骤：

1. 打开工程，双击 `Assets/Scenes/Level001.unity`，点击 Play。
2. 成功路径：能量每秒恢复，底部按钮按能量点亮；点击“突击兵”持续出兵，
   士兵沿浅色路径推进、攻击沿途防御塔；塔发射子弹反击。
   在倒计时归零前摧毁大本营，应出现“胜利”结算面板。
3. 失败路径：不部署任何士兵，等倒计时归零，应出现“失败”结算面板。
4. 暂停：左上角“暂停”按钮应冻结战斗（`Time.timeScale=0`），可继续或重新开始。
5. 存档：胜利一次后退出 Play 再进入，右上角应出现“本关已攻克”标记；
   存档位于 `Application.persistentDataPath/GameSave.es3`。
6. 胜利结算后请顺手停止 Play 并确认编辑器能正常退出（批处理环境下曾发现
   与 ES3.Editor 钩子相关的退出冻结，见 `DECISIONS.md`；交互式编辑器未复现确认）。
7. 尚未由真人验证的部分：真机触屏体验、难度手感、按钮触控热区大小、
   暂停/重试按钮的触屏手感。

## 运行时验证记录（2026-08-25，交接参考）

曾使用临时编辑器脚本 `SmokeTestRunner`（验证完成后已按规则删除）在
`-batchmode -nographics` PlayMode 中完整跑通 Level001，确认：

- 能量随时间恢复；部署扣能量；突击兵(50)/重装兵(120) 均可部署。
- 士兵沿路径推进，进入射程后停下攻击：三座塔先后被摧毁，大本营血量下降至 0。
- 塔发射追踪子弹击杀士兵。
- 倒计时归零前摧毁大本营 → `Won`（实测约 87 秒获胜）；不部署等归零 → `Lost`。
- 胜利自动写存档，重新加载可读回（`completed/wins/timeLeft` 正确）。

注意两条批处理环境经验（细节见 `DECISIONS.md`）：

1. 强制杀掉批处理 Unity 进程可能损坏 Bee 构建缓存，导致后续批处理“找不到
   新加的方法/类型”。处理：重跑一次，或先执行一次 `BuildAll` 触发重新编译。
2. 批处理中调用过 ES3 保存后，退出 PlayMode 会冻结（`ES3.Editor.dll` 的
   `playModeStateChanged`/`EditorApplication` 钩子在无头环境异常）。批处理验证
   必须以外部看门狗强杀收尾；交互式编辑器是否受影响待用户确认。

数值调整入口：`Assets/Game/Content/Definitions/` 下的定义资产
（士兵/塔/大本营/子弹/关卡），改后无需改代码。
重建场景入口：菜单 `AIOnly/构建垂直切片场景`（会覆盖手工场景修改）。

## 推荐里程碑

### M0：工程基线

- 确认并清除当前编译错误。
- 对 BaseFramework 其余模块做最小风险审查和必要修复（对象架构已完成首轮改良）。
- 确定屏幕方向、逻辑分辨率和首个垂直切片规则。

### M1：最小垂直切片

- 一张地图、一种单位、一种塔、一种部署资源。
- 可完成点击/拖动部署、路径推进、攻击、胜负、重试。
- 最小 HUD、暂停和关卡进度保存。

### M2：数据与内容生产管线

- 稳定内容 ID、ScriptableObject 定义和校验工具。
- 便捷的占位/正式素材替换。
- 数据驱动关卡、单位和防御塔配置。

### M3：成长与关卡选择

- 用户确认后的成长系统。
- 关卡解锁、奖励、教学状态与存档迁移。

### M4：内容扩展与 Android 打磨

- 扩展至约十余关和多种单位/防御塔/地形。
- 真机触控、性能、生命周期、安全区与资源导入打磨。

里程碑顺序可以调整，但每一阶段都应保持可运行和可由用户试玩。
