# 开发流程与状态

## AI 开发流程

1. 读取根目录 `AGENTS.md` 和本知识库相关章节。
2. 明确本次任务的玩家价值、范围和手动验收条件。
3. 检查现有代码与场景，优先扩展 `BaseFramework`，避免重复系统。
4. 先实现最小可玩闭环，再增加表现和扩展点。
5. 使用稳定内容 ID 和占位资源完成表现，不绑定最终素材。
6. 确认可用的编译/Console 状态，不以历史日志冒充当前验证。
7. 更新本文件的实现状态以及必要的决策记录。
8. 向用户说明改动、当前限制和短小的手动验收步骤。

## 用户手动验收模板

每个功能交付时应给出类似以下内容：

1. 用项目指定的 Unity 版本打开工程和指定入口场景。
2. 清空或观察 Console，进入 Play Mode。
3. 按明确操作完成成功路径。
4. 按明确操作覆盖至少一个失败或边界路径。
5. 退出并重新进入，若涉及存档则确认状态是否保持。
6. 涉及触屏差异时，在 Android 设备上重复关键步骤。

不是所有任务都需要六步；应根据改动缩减。

## 推荐里程碑

### M0：工程基线

- 确认并清除当前编译错误。
- 对 BaseFramework 做最小风险审查和必要修复。
- 确定屏幕方向、逻辑分辨率和首个垂直切片规则。

### M1：最小垂直切片

- 一张地图、一种单位、一种塔、一种部署资源。
- 可完成点击/拖动部署、路径推进、攻击、胜负、重试。
- 最小 HUD、暂停和关卡进度保存。

### M2：数据与内容生产管线

- 稳定内容 ID、ScriptableObject 定义和校验工具。
- 便捷的占位/正式素材替换。
- 数据驱动关卡、单位和防御塔配置。

### M3：成长与关卡选择

- 用户确认后的成长系统。
- 关卡解锁、奖励、教学状态与存档迁移。

### M4：内容扩展与 Android 打磨

- 扩展至约十余关和多种单位/防御塔/地形。
- 真机触控、性能、生命周期、安全区与资源导入打磨。

里程碑顺序可以调整，但每一阶段都应保持可运行和可由用户试玩。
