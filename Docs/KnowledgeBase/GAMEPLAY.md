# 玩法框架

## 已确认的宏观结构

玩家处于进攻方，在俯视角地图中通过轻量点击、滑动和 UI 操作组织进攻，突破由
防御塔和地形构成的关卡。内容由简单教学逐步扩展至复杂塔型和复杂地形，并包含一套
成长体系。

## 已确认：首个垂直切片规则（2026-08-24）

以下规则由用户通过参考图与文字确认，已实现为 M1 垂直切片（入口场景
`Assets/Scenes/Level001.unity`）：

1. 深红色方块是敌方防御塔。塔自动发射子弹攻击玩家士兵，保卫大本营。
2. 浅蓝色方块是玩家士兵。士兵生成后从当前位置直线向敌方大本营推进；进入配置的
   塔吸引范围后转向防御塔，攻击目标始终优先选择防御塔，范围内没有防御塔才攻击大本营。
3. 屏幕顶部是能量条。能量随时间恢复（8/秒，上限 200，开局 100），部署士兵消耗
   能量；当前能量达到不同兵种的消耗阈值时能量条变色，点击地图会生成当前能量可
   负担的最高阶兵种（突击兵 50、重装兵 120、精英兵 180）。
4. 屏幕右上角是倒计时（99 秒）。归零前未摧毁大本营则失败。
5. 胜利条件：摧毁敌方大本营；失败条件：倒计时结束。
6. 部署方式：鼠标左键或单指点击地图任意非 UI 位置，在点击处生成当前能量档位的
   士兵；士兵生成后完全自动行动，玩家不中途操控。暂停、重试等 UI 操作不穿透到战场。
7. 屏幕方向：横屏（参考图为横屏；工程设置 LandscapeLeft）。

所有数值与行为均数据驱动（模块结构见 `TECHNICAL.md`）。后续细化规则时优先修改
定义资产（`Assets/Game/Content/Definitions`），仅当现有字段不足时才改代码。

## 默认设计方向（尚非最终规则）

在用户确认具体规则前，开发应围绕以下最小闭环保持可扩展性：

1. 进入关卡并观察地图、进攻起点、目标和敌方防御。
2. 玩家消耗某种局内资源选择并部署进攻单位或进攻方案。
3. 单位直线向目标推进，靠近防御塔时按塔吸引规则改变方向，防御塔自动选择目标并攻击。
4. 玩家通过有限且轻量的操作调整后续部署或触发能力。
5. 达成目标后胜利；进攻资源耗尽或满足失败条件后失败。
6. 结算关卡结果，写入进度与成长数据，再进入下一关或重试。

该闭环只用于约束系统边界；已确认的首关规则以本文件和 `DECISIONS.md` 为准，后续新增资源、塔位规则和能力仍需按 `OPEN_QUESTIONS.md` 逐项确认。

## 已确认：点击部署与三档能量（2026-08-29）

1. `Game.Input.BattleInputManager` 继承 `BF.InputManager`，复用基础输入管理器的
   鼠标/触摸点击语义，并将屏幕坐标转换为战场世界坐标。
2. 点击战场后，`BattleFlow` 从首关 `deployableSoldiers` 中选择当前能量可负担的最高
   `EnergyCost` 兵种，扣除该消耗并在点击位置生成对应 Prefab；不再接入或依赖关卡路径点。
3. 三档颜色由各 `SoldierData.TierColor` 配置：突击兵蓝色（50）、重装兵金色（120）、
   精英兵红色（180）。能量不足以负担最低档时，点击不生成士兵，能量条显示灰色。
4. 士兵移动由 `SoldierMovementComponent` 处理：默认直线前往大本营，进入
   `SoldierData.TowerDetectionRange` 后转向最近的塔；`SoldierMeleeAttackComponent`
   在攻击范围内按塔优先、大本营兜底的顺序索敌。

## 关卡递进建议

- 教学阶段：一次只引入一种操作或一种规则。
- 基础阶段：组合少量单位、基础塔和简单岔路。
- 中期阶段：加入塔之间的协同、射程覆盖、特殊地块或多目标压力。
- 后期阶段：组合复杂地形、复杂塔型、资源限制与多个战术目标。

关卡不能只靠提高生命和伤害制造难度。优先通过新关系、新限制和不同解法增加深度。

## 数据驱动边界

以下内容应设计为可配置数据，不直接写死在场景脚本中：

- 进攻单位属性、能力、占位与正式资源 ID。
- 防御塔属性、索敌规则、攻击方式和资源 ID。
- 关卡地图引用、塔位、大本营位置、可部署区域、初始资源和胜负条件。
- 关卡解锁、奖励与成长配置。
- 全局数值曲线及中文显示文本。

优先使用 ScriptableObject 定义静态配置。运行时状态和存档数据使用独立的普通 C#
数据结构，避免直接序列化场景对象或 ScriptableObject 实例。

## 移动端交互约束

- 鼠标左键与单指触摸必须走同一套语义层：按下、移动、释放、点击和拖动。
- UI 触摸不得穿透至战场操作。
- 不依赖鼠标右键、滚轮、键盘或悬停提示完成必要操作。
- 拖动阈值应按屏幕 DPI 或合理的参考分辨率适配，不能只使用固定像素假设。
- 危险或不可逆操作应有明确确认或易于撤销。
- 双击和长按不是首选主操作，除非用户确认它们确实改善体验。

## 首个垂直切片建议

- 一张可完整通关和失败的地图。
- 至少一种进攻单位；当前首关使用突击兵、重装兵、精英兵三种能量档位。
- 一种防御塔。
- 一种部署资源。
- 最小点击或拖动部署操作。
- 基础战斗、目标、暂停、胜负结算和重试。
- 保存关卡完成状态与必要设置。

垂直切片规则应在 `OPEN_QUESTIONS.md` 的最高优先问题确认后再正式实现。
